## 1. 项目概述

### 1.1 一句话定位

**面向职业教育专业群学生与教师的「教学实训 × 岗位技能」一体化智能体应用平台**：以德智体综合评价与第二课堂学分数据为底座，以多角色工作台为入口，以「发展助手」为成长主线，以 LLM、RAG 与个性化推荐为智能引擎，围绕**人才培养方案优化、岗位能力图谱、学习型任务生成、个性化自适应学习**四大场景，构建「画像认知 → 岗位洞察 → 能力补强 → 资源供给 → 路径规划」的完整成长闭环，落实**以岗定教、岗课赛证融通**的职教理念。

### 1.2 演进逻辑：从「管理」到「成长」

平台在传统成绩管理系统（用户认证、角色权限、成绩录入查询、附加分审批）之上，完成了三层跃迁：

| 阶段 | 形态 | 代表能力 |
| --- | --- | --- |
| 1.0 数字化 | 数据管理 | 成绩导入、学分规则、附加分工单闭环、公告触达 |
| 2.0 数据化 | 数据洞察 | 综合测评快照、多维统计分析、班级风险预警 |
| 3.0 智能化 | **智能成长** | **发展助手、AI 对话助理、长期记忆、RAG 知识库、岗位推荐、AI 时光机、个性化成长链路** |

平台的内核已不再是「录入与查询」，而是**「理解每一个学生，并为其生成下一步行动」**。

### 1.3 核心价值主张

- **对学生**：一个有记忆、懂你数据的 AI 助教，一条看得见步骤的成长链路，一份由真实学情驱动的个性化岗位与学习资源推送。
- **对教师**：自定义画像规则 + 班级学情摘要 + AI 待办洞察，把「凭经验育人」升级为「凭数据育人」。
- **对管理者**：全校数据画像、AI 知识库治理、对话日志反馈闭环，让 AI 能力可运营、可审计、可迭代。

### 1.4 与竞赛榜题的对齐：四大典型场景全覆盖

本项目对标挑战杯「揭榜挂帅」专项赛榜题 **XA-202603《面向职业教育高水平专业群建设的教学实训与岗位技能智能体开发》**（发榜单位：科大讯飞，2026 赛季），平台四类核心 AI 能力恰好**完整覆盖**榜题要求的四个典型开发场景：

| 榜题典型开发场景 | 平台对应落地模块 | 落地状态 |
| --- | --- | --- |
| ① **人才培养方案智能优化** | 岗位需求情报站：DeepSeek-Reasoner 联网实时采集主流招聘平台近一周岗位与技能要求（§5.5）+ 管理端专业建设数据底座 | 数据采集与趋势分析就绪；「技能热度曲线 / 专业预警 / 优化建议」看板纳入 §9.2 演进 |
| ② **挖掘岗位能力生成岗位能力图谱** | 能力图谱组件（岗位 skills → 技能节点 → 学习入口）`JobSkillMindMap` + 学生八维能力雷达（§5.7） | 完整落地：图谱为前端 SVG 可视化（静态 tips + 文档/掘金/MDN 链接）；八维雷达由画像 AI/规则生成 |
| ③ **岗位典型工作任务 → 学习型任务** | AI 学习任务卡：企业真实任务 → 课堂实训分步拆解（§5.6），配套 RAG 知识库依据溯源（§5.4） | 完整落地，即「以岗定教」的核心载体 |
| ④ **个性化自适应学习** | 发展助手成长链路：目标画像 + 六维资源 + 三级进度 + 微课/仿真路径 + AI 长期记忆（§4 / §5.3） | 完整落地，「千生千面」式供给，含进度条与每日打卡的成长可视化 |

同时，平台在工程上对齐榜题的功能与技术硬性要求：

- **场景真实性**：AI 的全部输入来自真实业务数据（学情、第二课堂学分、附加分工单、真实招聘情报），痛点源自教学与就业一线，杜绝虚构空泛场景。
- **功能闭环性**：对话助理实现「用户输入 → 内置知识库/工具调用 → 逻辑处理 → 生成结果 → 溯源反馈」的完整微任务闭环（§5.2）。
- **内容专业性**：RAG 知识库以「知识库 → 文档 → 分段」承载领域知识并支持来源标注，回答随附「知识库依据」引用，做到"说得清、有依据、能落地"（§5.4）。
- **交互友好性**：多轮对话 + 长期记忆 + 口语化有温度的表达 + 快捷指令，支持模糊提问澄清与追问（§5.2 / §5.3）。
- **MVP 可运行**：平台为可独立部署的全栈智能体应用（React 19 + Spring Boot 3.2 + DeepSeek），满足"可运行、可交互的最小可行产品（MVP）"要求，可直接提供在线 Demo 体验入口。

评审指标（功能完整性 30 / 技术实现与内容质量 50 / 应用潜力与完成质量 20）与提交材料（01–06）的自评对照详见 **§9.3**。

### 2.3 设计原则

1. **AI 原生，但优雅降级**：所有 AI 能力（对话、推荐、画像、时光机）都配置了规则引擎 / 示例数据 / 最近缓存兜底，AI 不可用 ≠ 功能不可用。
2. **数据驱动，防幻觉优先**：LLM 只被允许基于注入的「真实数据摘要」与工具返回结果作答，未命中数据必须明示"无法查询"，从 System Prompt 与工具链两层约束。
3. **个性化优先**：一切推荐信号均来自学生真实行为（收藏岗位、学习进度、画像维度），而非冷冰冰的全量推送。
4. **成本可控**：Redis 配额限流（时光机每日）、全局 AI 并发门控（Semaphore）、embedding token 预算、无效输出熔断，全链路防"失控调用"。
5. **软件工程默认域**：对话助理、岗位推荐、任务卡与学习资源 Prompt 统一约束为 SE / 互联网研发方向，避免模型飘到销售、硬件产线等无关岗位。

## 3. 核心业务域（基础能力）

### 3.1 多角色工作台

系统内置四级角色模型，每一角色都有独立工作台入口与数据边界：

| 角色 | 工作台能力 |
| --- | --- |
| 管理员 | 学院/专业/班级/年级/课程/用户全量治理、成绩与第二课堂导入、综合测评配置、附加分模板与审批、AI 知识库与对话日志、邮件与系统配置 |
| 教师 | 班级学情统计、附加分待办审批、**自定义学生画像规则**、**AI 班级答疑总结（教师 AI 报告）**、按班查看对话日志 |
| 班委 | 班级成绩录入、统计看板、导出、成绩核对 |
| 学生 | 成绩/趋势/排名、第二课堂进度、附加分工单办理与历史、公告通知、**发展助手（成长主入口）** |

### 3.2 成绩与测评域

- **成绩管理**：Excel 多格式导入（Apache POI，带预览与批次）、RAIN 结构化学业数据、按学期成绩趋势与班级风险预警。
- **第二课堂学分**：规则配置 + 批量导入 + 学分进度可视化。
- **综合素质测评（德智体）**：权重可配置（`CompositeScoreWeight`），附加分折算，**定时快照刷新**（`CompositeScoreSnapshotScheduler`）保证查询性能与历史可回溯，快照刷新日志可审计。
- **附加分工单闭环**：提交窗口（`ExtraScoreSubmissionWindow`）→ 模板（德育/智育/体育 × 组 × 条目 × 作者级别规则）→ 学生申请（证据文件上传 COS）→ 教师/管理员审批工作台 → 事件日志 + 有效分折算 → 历史数据迁移。

> 业务域不是本文重点，但它是智能层的**数据底座**：没有这套完整闭环，§4–§6 的画像、推荐与对话就没有可信数据来源。

## 4. 发展助手：一站式成长工作台（核心亮点 ①）

「发展助手」是本平台面向学生的**一体化成长工作台**（`/student/assistant`），将分散的数据能力串成一条**可感知、可执行、可追溯**的成长链路，并内嵌 AI 对话与时光机，形成"**认知 → 选择 → 行动 → 反馈**"的闭环。整体设计呼应职业教育**「以岗定教、岗课赛证融通」**理念——岗位需求进课堂、课堂任务出岗位，是榜题 XA-202603 场景②③④的核心承载体。

### 4.0 产品形态：侧栏多视图 + 六步叙事

发展助手**不是单页六步向导**，而是侧栏切换的多视图工作台（`VIEW_META` / `ASSISTANT_NAV_GROUPS`）：

| 导航分组 | 内部视图 | 说明 |
| --- | --- | --- |
| 我的工作台 | 首页概览、学习记录 | 雷达 / 语言热度 / 进度汇总；按收藏岗位看完成明细 |
| 岗位探索 | 热门岗位、我的收藏 | 近一周热招 + 收藏管理；概览默认聚焦首个收藏岗 |
| 成长行动 | 岗位成长链路、岗位学习资源 | 六步链路全景 + 六维资源 / 微课阅读器 |
| AI 能力 | AI 对话、AI 时光机 | 与独立对话页共会话；反事实未来推演 |

六步成长链路是其中的**叙事主线与可视化骨架**（概览顶栏 `CHAIN_STEPS` + `growthPath` 视图），把各视图串成可讲清的产品故事。

### 4.1 六步成长链路

```
我的画像 ──► 热门岗位 ──► 能力图谱 ──► 学习任务卡 ──► 学习资源 ──► 个性化路径
（认识自己）  （看懂市场）  （拆解差距）  （模拟实战）  （补齐弹药）  （持续迭代）
```

| 环节 | 设计意图 | 技术要点 |
| --- | --- | --- |
| **我的画像** | 用八维雷达图让学生直观认知自身优劣势 | ECharts 雷达图；读库中最新 `StudentAnalysisRecord`（§5.7） |
| **热门岗位** | 每周一自动刷新 TOP5 热招岗位，可收藏 | AI 联网检索 + 定时调度 + 无效输出熔断（§5.5） |
| **能力图谱** | 岗位 → 技能 → 学习入口的分层心智模型 | `JobSkillMindMap` 纯前端 SVG：解析 skills + 静态 tips / 外链 |
| **学习任务卡** | AI 生成「企业真实任务 → 课堂实训步骤」 | DeepSeek 生成；前端分阶段进度为**体验模拟**，非后端真实百分比（§5.6） |
| **学习资源** | 六维定制资源（理论/实战/技能/项目/行业/路径） | AI 聚合外链 + `MicroCourseReader` 图文微课（解锁载体） |
| **个性化路径** | 微课 → 仿真 → 实训的进阶路径，标记完成形成进度 | 学习进度追踪 + 资源解锁 + 防刷校验（§6） |

### 4.2 个性化闭环机制

发展助手的个性化不是"千人一面"的静态页面，而是**由学生行为实时驱动的动态引擎**：

1. **收藏即信号**：学生收藏岗位后，系统解析其技能标签（`parseSkills`），形成个人技能画像集合。
2. **技能重叠推荐**：`relatedHotJobs` 基于"与已收藏岗位技能重叠、但尚未收藏"的实时计算，自动推荐关联热招岗位——推荐理由天然可解释。
3. **链路联动**：概览工作台默认聚焦第一个收藏岗位，能力图谱、任务卡、资源、路径全部围绕该岗位展开，形成"选定方向 → 深度供给"的聚焦式体验。
4. **进度即反馈**：任务步骤、资源完成、路径节点三级进度实时回写，学习记录视图可按岗查看。
5. **防刷与习惯养成**：学习完成须先解锁资源（`RESOURCE_UNLOCK`）；每日打卡（`DailyCheckinCard`，洛谷风运势宜忌 + 连续天数）与学习完成**同表整合但不互为门槛**——打卡激励习惯，不拦截资源/任务完成。

### 4.3 与 AI 的深度内嵌

发展助手将 AI 能力作为一等公民内嵌：**AI 对话**与独立对话页共享会话历史，可直接在工作台内提问；**AI 时光机**入口一键进入"如果…"推演（§5.9）。AI 不再是旁路工具，而是成长链路的"随行教练"。

## 5. AI 能力矩阵（核心亮点 ②）

平台的智能层构建在**一套自研的 LLM 接入抽象 + 九大 AI 能力**之上，逐项说明方案与技术。

### 5.1 LLM 接入层：Provider SPI 抽象

所有对话与推理能力收敛到统一门面 `LlmChatService`，通过 SPI 接口实现**模型提供商可插拔**：

```
LlmModelProvider (SPI)
 ├── DeepSeekModelProvider       deepseek-chat（同步 + SSE 流式，生产默认）
 ├── OpenAiCompatibleProvider    OpenAI 兼容协议（可指向任意兼容网关）
 └── MockModelProvider           本地开发/降级，返回结构化示例
```

- **设计要点**：`@PostConstruct` 自动注册发现，运行时按 `ai.chat.provider` 配置选择；流式与同步双超时通道（20s 同步 / 60s 流式）隔离治理；生产环境默认**关闭 Mock 静默降级**，模型异常直接报错，避免"看似正常实则误导"。
- 统一的消息模型（`Message` / `ChatRequest` / `ChatResponse`）、流式事件模型（`StreamEvent`）与**工具调用模型**（`ToolDefinition` / `ToolCallRequest` / `StreamToolCallAccumulator`）为上层所有 AI 能力提供一致底座。

### 5.2 AI 对话助理：有工具、有记忆、防幻觉

采用**双通道**策略差异化服务不同场景：

| 通道 | 定位 | 能力 |
| --- | --- | --- |
| **悬浮球**（floating） | 全局悬浮常驻、随行问答（跨页面） | 无工具调用，轻量口语化 System Prompt，会话 TTL 1 天 |
| **页面对话**（page） | 深度成长对话 | 工具调用 + RAG 检索 + 长期记忆，会话 TTL 30 天 |

**核心技术方案：**

- **SSE 流式输出**：基于 `SseEmitter` 逐 token 推送，配合前端打字机渲染，对话体感"快"。
- **Function Calling / Tool Loop**：模型可调用 13 类业务工具——学生端（成绩查询/全部成绩/学期趋势/第二课堂进度/附加分进度）、教师端（班级信息/班级成绩统计/待审批明细）、管理员端（全校概览/待审批明细）、通用（公告查询）以及 page 通道专属的 `knowledge_search`（RAG 深挖）与 `memory_search` / `memory_get`（记忆取证）。工具循环上限 3 轮，防无限调用。
- **工具轮文本治理**：模型在调用工具前常输出英文计划句（"I'll query…"），系统会在工具轮**丢弃这类过渡文本**，只把工具调用写入上下文，保证最终回答纯净。
- **交互友好性（赛事对齐）**：System Prompt 强制"自然口语、有温度、短句优先"的表达风格，避免公文腔与术语堆砌；依托多轮会话历史与长期记忆（§5.3）支持模糊提问澄清与 2–3 轮追问，分步骤输出重点，贴近高职学生认知习惯。
- **实时数据摘要注入**：后端按角色实时构建结构化摘要（学生：成绩统计/趋势/风险预警/第二课堂/附加分摘要/综合测评；教师：班级统计/待办；管理员：全校概览），注入 System Prompt，让 LLM "带着数据说话"。
- **防幻觉四重约束**：① 只允许基于摘要/工具返回回答；② 摘要缺失必须回应"暂时无法查询到该数据"；③ 涉及数字必须以摘要或工具返回为准；④ 快捷指令前缀（`[query_score]` 等）只发 LLM、不污染历史与列表标题。
- **会话治理**：Redis 会话（TTL 分通道），**会话所有权校验**防越权，支持列表/重命名/删除；前端本地存储按键按用户隔离，切号不串会话。
- **运营闭环**：每次对话落库 `KnowledgeChatLog`，并按**学号 / 班级 / 姓名**三重记录归属；管理端"AI 对话日志"页可查看与标注反馈（GOOD/BAD），学生端消息支持 👍/👎 即时反馈并展示**模型名、耗时、引用来源**等元信息，支持复制 / 重新生成；对话日志更可下沉为教师侧班级学情分析的数据源（§5.10），形成「学生提问 → AI 解答 → 班级归集 → 教师干预」的完整运营飞轮。
- **快捷提问**：前端 `QUICK_COMMANDS` 提供"查询本学期成绩 / 高数成绩是多少 / 班级成绩排名 / 查看附加分申请进度"等一键指令。

### 5.3 长期记忆系统：仿 OpenClaw 架构

这是平台最具前瞻性的设计之一——让 AI **跨会话记住学生**，实现"越聊越懂你"。

```
Redis 三层记忆结构（仿 OpenClaw 的 MEMORY.md + memory/YYYY-MM-DD.md）
 ├── assistant:memory:{uid}:page:long      长期摘要（Markdown bullet，注入每次对话）
 ├── assistant:memory:{uid}:page:index     ZSet 日期索引（score=最后更新时间）
 └── assistant:memory:{uid}:page:bullets   dreaming 压缩后的最新子弹笔记
```

- **Dreaming 记忆固化**：每攒够 N 条用户消息（默认 6 条）触发一次"梦境压缩"（`AssistantMemoryConsolidationService`），把会话历史压缩为要点子弹存入长期摘要——记忆会"自动生长、自动遗忘"，TTL 90 天，容量上限 30 条 / 1600 字符。
- **零依赖检索**：记忆检索采用 **TF-IDF 风格的关键词打分**（子串 + 字符重叠），刻意不引入 embedding 依赖，在记忆场景做到"够用且快"。
- **工具取证**：模型可主动调用 `memory_search` / `memory_get(date)` 回查历史会话摘要，回答"你上次说想考研"这类跨会话问题。
- **隐私设计**：记忆按 user 维度隔离，`longTermSummary` 仅注入本人会话。

### 5.4 RAG 知识库：MaxKB 式三级结构

面向「软件技术专业群教学实训与岗位技能知识」构建**可运营的领域知识库**，让 AI 回答有据可依、可溯源。

- **三级结构**：知识库（知识域）→ 文档（PDF / Word / TXT / Markdown）→ 分段（内容切块），完全对齐社区主流 RAG 平台 MaxKB 的分层模型。
- **智能切块**：按句末标点优先切块（450 字符/块 × 上限 500 块/文档），切块标题按句边界截断预览，兼顾向量预算与语义完整性。
- **向量化**：OpenAI 兼容 Embedding API，默认 `BAAI/bge-m3`（SiliconFlow），向量 JSON 直存 MySQL 分段表，**embedding 不可用时自动降级为关键词检索**。
- **检索策略**：`top-k=3` + 相似度阈值 0.3 过滤（低于阈值的"伪依据"不返回），命中文档去重后作为**知识库依据**随回答下发，前端展示引用来源。
- **管理端治理**：知识库 CRUD、分段级"查看/编辑/启停/删除/向量化"，管理员可在页面直接配置 embedding（Key / 网关 / 模型），无需改代码；历史数据已统一治理（旧知识条目结构精简收敛）
- **内容专业性（赛事对齐）**：分段即**结构化领域知识条目**，可嵌入课程标准、职业技能等级证书要求、实训指导书、行业规范等权威素材（脱敏后），并支持标注来源（教材页码 / 标准文件编号）；回答随「知识库依据」溯源下发，知识条目规模可按专业群持续扩充至 50 条以上，直指赛事"内容专业性"评分项——"说得清、有依据、能落地"。
- **双路注入**：page 通道对话默认开启 RAG 检索注入；同时暴露 `knowledge_search` 工具供模型按需深挖，注入与工具互补。

### 5.5 岗位推荐引擎：AI 联网检索 + 调度 + 熔断

- **方案选型**：数据源抽象为 `WeeklyJobRecommendationClient` 接口；**默认** `provider=deepseek` → `DeepSeekWeeklyJobRecommendationClient`（**deepseek-reasoner + 联网搜索**），检索 BOSS直聘 / 猎聘 / 前程无忧近一周**软件工程 / 互联网研发**新发岗位。`McpJobsWeeklyJobRecommendationClient`（mcp-jobs 爬虫桥）仍可配置切换，yml 已标「废弃」。岗位推荐 / 学习资源 / 任务卡由 `JobRecommendationConfig` 统一装配。
- **领域约束**：Prompt 与兜底示例均锁定 SE 细分方向（后端 / 前端 / 测试 / DevOps / 全栈等），排除销售、硬件产线、非研发岗位编造。
- **定时调度**：`WeeklyJobRecommendationScheduler` 每周一 06:00 自动刷新（cron `0 0 6 ? * MON`）。
- **数据保留**：刷新成功后 `cleanupOldData(1)`，**库内只保留最近 1 周**岗位数据。
- **Prompt 工程**：约束输出"具体到业务方向的 TOP5 岗位 + 薪资 + 技能 + 可访问详情链接"，且**只输出 JSON**；无法获取真实数据必须返回 `[]`，严禁编造。
- **无效输出熔断**：命中占位短语库（"暂无 / 无法提供 / 需人工检索…"）的输出**直接拒绝落库**。
- **兜底策略**：完全失败时回退内置 SE 示例岗位（标记 `system-fallback`）；自动刷新失败保留上周数据不白屏；手动刷新 **10 分钟冷却**。
- **前端联动**：热招列表与收藏岗位技能重叠实时计算（§4.2），一键跳转 BOSS直聘搜索页。
- **场景①的数据底座（赛事对齐）**：持续采集真实社会岗位需求与技能要求，可衍生「技能热度曲线 / 专业预警 / 培养方案优化建议」看板（演进见 §9.2）。

### 5.6 岗位 AI 内容生成：任务卡 + 六维学习资源

发展助手最"重"的生成能力，全部围绕**学生已收藏的方向**定制，客户端均为 **纯 DeepSeek（reasoner 联网链路）**，无 MCP：

- **学习任务卡**（`JobTaskCard` / `DeepSeekJobTaskCardClient`）：「企业真实软件研发任务 → 课堂可执行实训步骤」；刷新时可并入「已掌握路径步骤」以生成衔接进阶、不重复的下一步。前端多阶段进度条为体验模拟。
- **六维学习资源**（`JobLearningResource` / `DeepSeekJobLearningResourceClient`）：按 **理论 / 实战 / 技能 / 项目 / 行业 / 学习路径** 供给；外链以掘金 / CSDN / 博客园 / B 站等为主，缺链时可落平台搜索 URL。
- **图文微课**：`MicroCourseReader` 是前端阅读器与**解锁载体**（打开即写 `RESOURCE_UNLOCK`），保证"点开有内容可读"；它不是 DeepSeek 挂掉后的规则引擎降级。
- **并发门控**：`AiJobGenerationGate` 公平 `Semaphore`，**全局单路**（`job-ai.max-concurrent=1`，排队上限 240s）；`job-resource.read-timeout-ms=120000`。
- **配额体系**（任务卡与资源板块额度互相独立）：
  - 任务卡：板块池 **5 次/天**（生成+刷新合计）；刷新类型另限 **3 次/天**。
  - 学习资源：板块池 **5 次/天**（AUTO+MANUAL+REGENERATE）；手动刷新 / 重新生成各限 **3 次/天**。

### 5.7 学生画像分析：八维雷达 + 批量分析

- **数据底座**：聚合德育 / 智育 / 体育成绩、RAIN 结构化学业数据、已审批附加分，构建多维特征快照。
- **八维能力雷达**：思想品德、发展潜力、综合素质、技能素养、文体素养、实践服务、科研创新、学业成绩——由 `DeepSeekAnalysisClient` 推理；失败或未配置时 `buildFallbackResult` 规则兜底。
- **触发与展示**：学生端 `GET /student/analysis/profile` **只读最新快照**，不在打开页面时现算；主触发为管理端/教师端「更新画像 / 批量更新」，时光机首次无画像时也可附带生成。
- **批量分析**：`CompletableFuture` + 批任务状态机，整班/整院可查进度。
- **隐私红线**：画像 payload **不采集手机号/邮箱等 PII**（§7）。

### 5.8 企业画像匹配：规则引擎 + 教师自定义

- **可解释的匹配引擎**：`StudentPortraitMatchService` 基于竞赛 / 技术 / 就业 / 服务四大关键词域（挑战杯、互联网+、蓝桥杯、实习、志愿…）做轻量规则匹配，输出「技术型 / 竞赛型 / 就业型 / 服务型」等可解释画像标签——不依赖黑盒，任何结论都能说清依据。
- **教师自定义规则**：教师可配置专属画像规则（`TeacherPortraitRule`），系统自动关联学生所属教师使自定义规则生效——**育人经验数字化**。

### 5.9 AI 时光机：反事实未来推演

面向"如果我现在开始…会怎样"的成长决策场景：

- **推演逻辑**：以真实画像（复用 §5.7 结果）为基准，叠加用户设定的假设参数（如"坚持每周刷 10 道算法题 / 参加竞赛"），推演**未来各发展路径（考研/考公/竞赛/就业）的概率变化、八维雷达变化、未来时间线与 AI 点评**——纯实时计算，不落库。
- **成本护栏**：Redis 按"用户 + 日期"配额限流（默认 10 次/天，配置项 `ai.timemachine.daily-quota`，代码默认值；yml 可按需补声明），键内带日期天然按天失效。
- **优雅降级**：DeepSeek 不可用时自动切换到**规则引擎推算**（雷达与概率均本地计算），功能永远可用。

### 5.10 教师 AI 班级学情分析（班级答疑总结）

面向教师端的新一代 AI 洞察能力：把「学生与 AI 的对话」当作**最真实的学情信号源**，自动沉淀为可读、可追溯、可回看的班级报告，实现"数据反哺教学"。

- **对话归集与归属**：学生页面聊天日志随身携带**学号 / 班级 / 姓名**三重归属字段（`KnowledgeChatLog`），服务按班级花名册归集会话——班级名、学号、姓名三重匹配兜底；归属缺失的对话单独计数并在结果中提示（引导补全归属后重新生成，杜绝"漏统计"）。
- **LLM 结构化总结**：将最多 400 轮班级对话按时间正序送入大模型，生成固定结构的《班级答疑分析》——**一、班级疑惑**（高频知识点与制度理解不清点）｜**二、典型问题**（代表性现象与涉及面）｜**三、学情观察**（提问频率、内容深浅、关注方向）｜**四、给老师的建议**（可操作的教学与管理动作），并以 3000 token 上限约束单次生成成本。
- **证据纪律（Prompt 级防过度解读）**：生成提示词内置五条硬约束——只陈述对话中可直接观察的行为；把"同一诉求间隔数小时再次提问"默认视为正常复核而非"焦虑 / 路径不清"；禁止用单科成绩反推动机；样本过少必须明示"样本有限"而不得上升为班级共性；统一采用中性克制措辞。这与对话助理的防幻觉约束一脉相承，是平台「负责任的 AI」工程理念在教师侧的又一落地。
- **通用报告表设计**：报告历史落在统一表 `teacher_ai_reports`（以 `reportType=CLASS_ANSWER_SUMMARY` 分区），支持按教师 / 班级 / 时间段检索与回看；「禁止一事一表」——新增同类教师报告类型**零迁移复用**，呼应本文档可拓展性设计（§9.3）。
- **双端可见**：管理端页面复用教师 API（`/api/teacher/...`）按班级查看对话日志、生成并回看班级报告，形成「学生提问 → AI 解答 → 班级归集 → 教师干预」的完整教学反馈闭环。

> 赛事注记：该能力直接服务榜题 XA-202603 场景①「人才培养方案智能优化」的**学情监测侧**——班级共性问题与教学建议可沉淀为专业建设与教案迭代的依据，同时天然满足赛事「验证与反馈」维度"真实用户、真实数据"的证据取向。

### 5.11 AI 能力 × 应用场景总览

| AI 能力 | 模型/技术 | 防滥用机制 | 降级策略 |
| --- | --- | --- | --- |
| 对话助理 | deepseek-chat + SSE + Function Calling | 工具轮上限、会话校验 | Mock / 报错明确 |
| 长期记忆 | 仿 OpenClaw + Redis + TF-IDF | TTL、容量上限 | 无记忆可用 |

| 任务卡/资源 | deepseek-reasoner（无 MCP） | 单路门控、板块 5/天 + 刷新/再生成 3/天 | 微课阅读器可读；失败返回可读错误 |
| 画像分析 | deepseek-chat + 特征快照 | 批任务状态机 | 规则引擎兜底雷达/摘要 |
| 画像匹配 | 关键词规则引擎 | 教师规则白名单 | 纯本地，天然可用 |

| 教师学情分析（§5.10） | Provider SPI（默认 deepseek-chat）+ 对话归属归集 | 会话量上限 400 轮、归属缺失提示 | 生成失败返回可读错误信息 |

## 6. 个性化引擎（核心亮点 ③）

### 6.1 三层个性化信号

| 信号层 | 来源 | 用途 |
| --- | --- | --- |
| 静态画像 | 专业 / 年级 / 画像维度 | 与岗位方向初步对齐 |
| 行为信号 | 岗位收藏、技能解析集合 | 驱动关联推荐与资源定制 |
| 进程信号 | 任务/资源/路径完成进度 | 供给的"下一步"与防刷校验 |

### 6.2 关键机制

1. **收藏驱动的聚焦供给**：所有 AI 生成（任务卡、学习资源）以收藏岗位为唯一上下文——**定制，而不是推荐列表**。
2. **技能重叠的实时关联**：前端实时计算 `favoriteSkillSet ∩ hotJobs.skills`，推荐理由可解释。
3. **能力图谱可视化**：`JobSkillMindMap` 将岗位 `skills` 字符串拆为「岗位 → 技能 → tips」三层 SVG；tips 来自硬编码学习入口表 + 模糊匹配，未命中则给掘金 / MDN 搜索链——**可视化拆解，非 LLM 现场生成图谱**。
4. **三级进度追踪**：任务步骤 / 资源完成 / 路径节点各自独立标记；打开微课写入解锁；取消完成不丢解锁状态。
5. **防刷校验**：`RESOURCE` 完成前必须存在对应 `RESOURCE_UNLOCK`；`itemKey` 校验归属；禁止经 complete 伪造解锁；打卡仅允许当天、`recommendationId=0`。
6. **每日打卡**：洛谷风运势宜忌 + 连续天数，落 `TYPE_DAILY_CHECKIN`；与防刷同表，**不作为学习完成门槛**。
7. **可视化成长反馈**：ECharts 能力雷达 + 语言热度排行 + 概览摘要卡片。

## 7. 数据、安全与隐私

| 维度 | 方案 |
| --- | --- |
| 认证授权 | 无状态 JWT（Auth0 java-jwt，8h 过期）+ 角色声明 + 前端路由守卫；密码 spring-security-crypto 哈希 |
| 数据边界 | 会话所有权校验、按用户/角色隔离的数据摘要、教师/管理员仅可见授权域 |
| **PII 保护** | 画像分析 payload 不采集手机号/邮箱；LLM 上下文仅注入必要学业维度 |
| **AI 防幻觉** | System Prompt 硬约束 + 工具结果优先 + 未命中必须明示，双通道一致 |
| 成本护栏 | Redis 配额（时光机每日）、并发门控（岗位 AI）、embedding token 预算、邮件队列节流 |
| 文件安全 | 附加分证明文件上传腾讯云 COS（服务端托管密钥），本地仅存引用 |
| 伦理合规 | 脱敏优先：不经脱敏的真实个人数据不参与外发与生成；AI 仅基于真实数据作答、不伪造学术数据；「AI 生成内容」标识纳入演进规划（§9.2），对齐赛事 05 号伦理与安全合规声明要求 |
| 可审计 | 对话日志全量落库、快照刷新日志、附加分事件日志、导入批次历史 |

## 8. 工程化与质量保障

### 8.1 稳定性的三件套：门控 · 超时 · 降级

- **门控**：`AiJobGenerationGate`（公平 Semaphore，单路 AI 生成）+ 邮件发送节流（800ms）+ 手动刷新冷却（10min）。
- **超时**：每路外部调用都有独立超时策略（同步对话 20s / 流式 60s / reasoner 联网 120s / 排队 240s），用"精确的超时矩阵"替代"一刀切"。
- **降级**：见 §5.11 汇总表，每条 AI 链路都回答了一个问题——**AI 挂了，用户还能不能继续用？**

### 8.2 测试与校验

- 根目录 `npm run check` 一键执行：前端 ESLint + Prettier 格式校验 + Vite 构建 + 后端 `mvnw test`。
- 前端纯函数逻辑（成绩分组、审批工作台、防刷策略、表单选项等）配 Node Test Runner 单测（`.test.mjs`）。
- 全量 lint 存在历史基线问题，日常改动按"相关文件 lint + 构建 + 后测"组合验证（见 `docs/code-check.md`）。

### 8.3 部署与运维

- Nginx 静态托管前端 + 反向代理后端（`nginx/` 配置 + `install-nginx-config.sh`）。
- 一键部署脚本族：`deploy-online.sh`、`check-online.sh`（健康检查）、`insert-admin.sh`（初始化管理员）。
- 数据库备份样例（`backup/marking-prod-*.sql`）；配置全部走环境变量（`JWT_SECRET / DEEPSEEK_API_KEY / DB_USERNAME …`），本地与生产用 `application-local.yml` 隔离。
- Redis 承载会话 / 记忆 / 限流，MySQL 承载业务与向量 JSON，双层存储各司其职。
